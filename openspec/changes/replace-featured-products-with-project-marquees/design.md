## Context

См. мотивацию в `proposal.md`. Опубликованная главная и актуальная локальная рабочая копия уже показывают роль AI Engineer и пять продуктов без ссылок на разборы кейсов. В `index.html` находятся текущая сетка `selected-grid`, стили прежней архивной бегущей строки и inline CSS. `i18n.js` содержит словари RU/EN. У проекта нет сборки, а `tests/test_site_integrity.py` проверяет структуру верхней витрины и отсутствие case-studies CTA.

## Goals / Non-Goals

**Goals:**

- Заменить одну крупную сетку на две плотные линии с понятной тематикой.
- Использовать локальные превью и существующие прямые публичные ссылки.
- Сохранить требования текущей витрины: AI Engineer, RU/EN и отсутствие кейсов.
- Обеспечить клавиатурный доступ, ручной просмотр на телефоне и reduced motion.

**Non-Goals:**

- Не менять hero, страницу для команд, архив, лабораторию, блог и старые страницы кейсов.
- Не менять пользовательские незакоммиченные правки вне витрины.
- Не добавлять внешние изображения, сборщик или runtime-зависимости.

## Decisions

### Two independent marquee tracks

Верхняя секция сохраняет `#products`, заголовок и ссылку на архив, но заменяет `selected-grid` двумя самостоятельными треками. Первый содержит плагины Obsidian, второй - остальные продукты. Это переиспользует уже существующие ключевые кадры marquee, но получит отдельные классы, чтобы не менять архивную ленту.

Альтернатива - дописать строки в архивную секцию - отклонена, потому что пользователь просит именно верхушку сайта, а навигация и hero уже ведут к `#products`.

### Full-tile native links with an inert duplicate track

Каждая плитка будет ссылкой `<a>` с изображением, подписью категории и названием. Для бесшовного цикла набор повторяется, однако его копия получает `aria-hidden="true"` и `tabindex="-1"`, чтобы не создавать дубликаты в keyboard navigation и дереве доступности.

Альтернатива - оставить вложенные отдельные ссылки сайта и GitHub - отклонена, потому что для компактной витрины важнее крупная понятная область нажатия.

### Local preview asset palette

Существующие снимки `assets/shots` используются для проектов, которые уже имеют свои обложки. Для остальных плиток добавляются две локальные сгенерированные обложки с несколькими визуальными фрагментами. CSS управляет кадрированием через `object-position`, сохраняя одну палитру Raincoat и исключая зависимость от сторонних хостов.

Альтернатива - загружать снимки с GitHub Pages и внешних сайтов - отклонена из-за нестабильности, CORS и медленной загрузки.

### Localization and regression guard

Новые названия строк, категории и текст действий добавляются в обе части `i18n.js`. Проверка целостности меняется с ожидания старой сетки на проверку двух линий, прямых ссылок и отсутствия `case-studies.html` на главной.

## Risks / Trade-offs

- Дублирование плиток может повторить контент для screen reader или Tab. → Повторный набор помечается как скрытый и не получает фокус.
- Анимация может мешать пользователям с чувствительностью к движению. → `prefers-reduced-motion` останавливает анимацию и возвращает ручную прокрутку.
- Небольшие превью могут быть обрезаны на мобильном экране. → Плитки используют фиксированное соотношение сторон, адаптивную ширину и проверяются на 320 px.

## Migration Plan

1. Заменить только содержимое и стили верхней витрины, добавить локальные изображения и переводы.
2. Проверить страницу через локальный HTTP-сервер, затем тесты проекта и строгую OpenSpec validation.
3. Commit, push и публикацию не выполнять без отдельного разрешения пользователя.
4. При откате вернуть `index.html`, `i18n.js`, тест и новые изображения к исходному состоянию.
