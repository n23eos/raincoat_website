## Context

Мотивация в proposal.md. Существуют пять статических HTML-страниц, встроенные CSS/JS и общий i18n.js. Аудит подтвердил исчезновение меню на мобильном, overflow сетки при 320 px, общие метаданные постов и неоправданно широкое позиционирование главной относительно team.html. Пользовательские правки team.html/i18n.js и posts уже присутствуют.

## Goals / Non-Goals

**Goals:** сохранить статическую доставку, существующие URL, RU/EN и личный стиль; добавить доказательства с источниками и ясную иерархию найма.

**Non-Goals:** runtime-фреймворк, обязательная сборка, внешние AI API, платная озвучка, изменение личных заметок или публикация.

## Decisions

- Общие assets/site.css и assets/site.js расширяют существующий nav. Используются нативные кнопки, aria-expanded/controls, Escape и восстановление фокуса. Это меньше дублирования, чем отдельная реализация в пяти страницах.
- Главную и team.html обновляет основной агент; сохраняются разделы экспериментов/архива, а верхние три карточки ведут на case-studies.html#flowspeech/#graph/#kaidzen. Существующие остальные showcase-продукты остаются во вторичной витрине.
- Кейсы используют собственные assets/cases.css/js и словарь страницы, общий i18n.lang/langchange для языка. Контент статичен по умолчанию. Первичные публичные репозитории проверяются read-only; benchmark не выдумывается. Интерактивный пример иллюстрирует проверку кандидатного AI-результата на фиксированных данных, без имитации живого LLM.
- PDF генерируются один раз существующими локальными инструментами с исходником и сохраняются в assets/resume/. Генератор не становится runtime-зависимостью. Недостающие биографические сведения опускаются.
- Hero использует poster как CSS фон; источник видео задаётся только при достаточной ширине и отсутствии reduced motion. Есть управление воспроизведением. Текстовая область затемнена независимо от кадра.
- Для блога необязательный локальный генератор создаёт статические article entry points с метаданными из posts/index.json; Markdown и legacy reader остаются источником содержимого. Новые страницы переиспользуют шаблон blog.html с корректной базой относительных URL и заданным slug. Совместимость важнее смены URL старых ссылок.

## Risks / Trade-offs

- Недостоверные маркетинговые числа → новые карточки без непроверенных счётчиков; подробности с источниками и датой проверки.
- Случайная потеря чужих правок → исходное состояние сохранено вне репозитория, каждый изменяемый файл имеет одного ответственного.
- Статические превью могут устареть → документированная необязательная команда регенерации и проверка соответствия метаданных индексу.
- Расхождение RU/EN → проверка переключения каждой новой секции, PDF и интерактивного примера.

## Migration Plan

Обычные статические файлы, публикация в рамках этой задачи не выполняется. Проверка через HTTP, read-only браузерные измерения ширины, keyboard/menu/demo сценарии. Затем строгая валидация, независимое ревью и архивирование только этого завершённого изменения.
