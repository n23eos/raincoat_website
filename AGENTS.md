# Raincoat: работа над будущими фичами

- Отвечай по-русски, кратко и по существу.
- Перед работой прочитай README.md, openspec/config.yaml и относящиеся к задаче спецификации в openspec/specs/; проверь git status.
- Новые фичи веди через OpenSpec: proposal → specs/design → tasks → реализация → проверка → архивирование. Используй проектные навыки в .agents/skills/openspec-*.
- CLI вызывай как `npx --yes @fission-ai/openspec@1.13.0`: заменяй этим префиксом `openspec` в командах навыков, если CLI не установлен глобально.
- Для создания изменения используй $openspec-propose, для реализации — $openspec-apply-change, для архивирования проверенного результата — $openspec-archive-change.
- Текущий прогресс фичи веди в её openspec/changes/<name>/tasks.md. STATUS.md содержит состояние подключения процесса.
- Сохраняй статическую архитектуру и чужие изменения. Не добавляй сборку или зависимости без необходимости.
- Для UI запускай сайт через HTTP и проверяй затронутые сценарии, RU/EN, узкий экран и ошибки браузера. Если проверка недоступна, укажи ограничение.
- Каталоги с точным именем !notes — личные заметки: не публикуй их содержимое; сохраняй в .gitignore паттерн `\!notes/`. Не удаляй уже отслеживаемые заметки и не снимай их с отслеживания без разрешения.
- Commit, push и deploy выполняй только при соответствующем разрешении пользователя.
